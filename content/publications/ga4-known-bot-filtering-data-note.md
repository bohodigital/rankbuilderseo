## Dataset and period

The source record is Google Analytics Help’s current “Known bot-traffic exclusion” page, checked on 2026-08-03.

Google states that traffic from known bots and spiders is automatically excluded from Google Analytics properties. It says the exclusion cannot be disabled and the amount excluded cannot be viewed. Identification uses a combination of Google research and the International Spiders and Bots List maintained by the Interactive Advertising Bureau. [@bot-ga-known]

The wording matters:

```text
known bots and spiders
to the extent possible
excluded volume unavailable
```

The documentation does not say:

```text
all automation is removed
every remaining event is human
the filter has perfect recall
```

This data note evaluates the measurement consequences of that boundary. It does not attempt to reverse-engineer the private classifier or assign a residual-bot percentage.

## Methodology

**Collection.** Events reach GA4 through browser tags, app SDKs, server-side systems, or Measurement Protocol implementations. Collection evidence answers whether an event arrived, not whether a person generated it. A normal-looking browser event can be generated by automation. A legitimate person can fail to generate an event because of consent, network failure, browser restrictions, JavaScript errors, or blocking software.

**Automatic processing.** GA4 applies known-bot exclusion before the owner sees reports. Because exclusion is mandatory and its volume hidden, the analyst cannot reconstruct the raw pre-filter total from the interface.

```text
collected candidate activity
minus undisclosed known-bot exclusions
equals reported processed activity
```

The equation describes product scope. It does not imply that every other processing rule is shown or that the difference can be calculated.

**Reporting.** Reports aggregate events under dimensions, attribution rules, identity settings, thresholds, and cardinality behavior. A clean-looking report is the output of several transformations, not a raw request ledger.

Session counts add another model. Google describes sessions as groups of user interactions associated with session identifiers and inactivity behavior. [@bot-ga-sessions] An automated client can still produce a session if it survives the known-bot filter, while a human journey can fragment into several sessions because of implementation defects.

**Corroboration.** Server access logs, CDN logs, fraud systems, CRM records, order systems, and Search Console can provide independent evidence. Google’s Search Console data documentation notes that Search Console performs its own processing, including eliminating duplicates and visits from robots, while Analytics records configured behavior from environments that can run the measurement code. [@bot-gsc-data]

The products should not be expected to match. Their differences are not a universal bot detector.

## Result

**The automatic control is real.** Owners do not need to enable a GA4 “exclude known bots” switch. The current product applies exclusion automatically. Migration guidance likewise distinguishes GA4 from Universal Analytics by stating that GA4 automatically excludes known bots. [@bot-ga-migration] This removes a class of routine crawler traffic without requiring a view filter.

**The control is not auditable from GA4.** The owner cannot see:

- which user agents were excluded;
- which requests matched;
- how many events were removed;
- when the bot list changed;
- a before-and-after total;
- false-positive or false-negative rates.

Therefore, the statement “Bot traffic fell by 14% after GA4 updated its list” cannot be established from the GA4 interface unless separate evidence measures the change.

**Remaining data are not certified human-only.** The phrase “known bots” creates a bounded class. Automation can be new, private, distributed, browser-based, deliberately human-like, sent through a server, generated by testing, caused by monitoring, or produced by internal tooling.

The documentation does not claim comprehensive detection of all these cases.

```text
GA4 reports exclude a documented class of known automation.
Unknown or unclassified automation may require separate detection.
```

That is an inference from stated scope, not a measurement of residual bots.

**Conversion rates can still be distorted.** Suppose:

```text
reported sessions = 10,000
reported key events = 200
reported rate = 2%
```

If 1,000 reported sessions came from unclassified automation that never converts, the human-session denominator would be smaller. If automated events fabricate conversions, the numerator can be affected instead. The example demonstrates sensitivity; it does not estimate a real property.

**Search traffic comparisons need product boundaries.** Search Console measures visibility and clicks in Google surfaces. GA4 measures configured on-site events after collection and processing. Consent, JavaScript, redirects, blockers, cross-domain setup, bot processing, and attribution can all create differences.

A Search Console click without a GA4 session is not automatically a bot. A GA4 session without a Search Console click is not automatically direct traffic. The systems use different scopes.

**Measurement Protocol needs its own controls.** Server-sent events do not inherit a magical human guarantee. Validate source systems, authentication secrets, event names, timestamps, transaction identifiers, duplication, test traffic, internal automation, and impossible values. The known-bot filter should not be used as the security model for an event-ingestion endpoint.

**Suspicious patterns are screening evidence.** Potential indicators include impossible event frequency, repeated identical paths, unsupported hostnames, sudden geography shifts, zero rendering resources, missing commerce records, data-center network ranges, or events without matching page requests.

Each has innocent alternatives. Monitoring, QA, accessibility tools, privacy software, corporate networks, shared devices, and integration errors can look unusual. A useful investigation asks whether several independent signals converge.

**Validation record.** Create a cohort table:

```text
date
hostname
landing page
source medium
country
device
browser
engagement time
events per session
conversion
server request count
user agent
network classification
CRM outcome
```

Preserve the query, filters, timezone, export date, and report scope. Without that record, later reviewers cannot distinguish changed traffic from changed analysis.

## Limitations

GA4’s bot filter is proprietary. The public source identifies inputs at a high level but does not publish a classifier specification. The IAB list is not a complete list of all automated behavior on the internet, and this note does not evaluate its current membership.

Server logs also have limits: shared IPs, proxies, privacy relays, spoofed user agents, incomplete retention, CDN sampling, and client-side activity without a matching page request can prevent clean classification.

A defensible report should say that GA4 automatically excludes known bots while the excluded volume and exact classification remain unobservable, and that residual suspicious traffic was evaluated using independent signals. It should not say that every reported session is a person. The first statement has boundaries. The second has confidence, which remains the cheapest column in an analytics export.
